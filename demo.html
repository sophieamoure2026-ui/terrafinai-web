DEMO WALKTHROUGH — ZERO-COST BUILD · STATIC SITE · NO BACKEND

Demo Walkthrough

The working demo of the five adopted features — tiered data room, virtual deal rooms, verification dossiers, prospectus builder, private buyer CRM. Click through in order; each step says what to do and what it proves. Everything runs in the browser: no accounts, no paid services, no hosting spend. Reset the demo any time with the button at the bottom (or in the back office) — it clears access tiers, the activity log, CRM edits, and diligence flags in this browser.

Demo data only: buyer records are fictional samples (`.invalid` emails). Mandate figures are the verified figures on file — anything not verified reads UNVERIFIED. Simulated activity is tagged DEMO SIMULATION in the activity log and must never be presented to a seller as real buyer activity.
01 Deal rooms — one room per mandate

Open the Deal Rooms index and enter the Starhotels room. You see the teaser, the tiered document library (locked rows show what each tier unlocks), bidder instructions, and the engagement panel. Click VIEW on the Teaser and on the Mandate Summary — both expand in place. Try the Germany room too: its financials document now shows the real verified figures on file (aggregate, Waldorf, the 152-vs-232 key dispute).

What it proves: the RCM-style room works end to end on a static site, and no document link is ever faked — entries without a file on record render as locked / “provided after” states, never as downloads.

02 Tiered data room — register → e-NDA → approval

Open the Starhotels data room. Tier 1: register — try a Gmail address first and watch it be refused, then register with a corporate address (e.g. jane@axaim.com, firm AXA IM Alts). The registered buyer pack appears with the key figures. Tier 2: read the NDA template, add a LinkedIn URL, type-to-sign. The full verified-figures table unlocks. Tier 3: confirm you can provide financial-capability documentation and request approval — the pending state shows.

What it proves: the LoopNet-style four-tier gate works, with the corporate-email check and the e-NDA flow. The e-NDA here is a simulated signature (type-to-sign + checkbox, template text) — a binding signature needs the e-signature service in DECISIONS.md.

03 Back office — approve, shortlist, post diligence

Open the back office (Mandate Desk) and scroll to Pending approvals. Approve the Starhotels request — and add it to the shortlist. Then post new diligence for Starhotels (“Verification dossier published”). Go back to the Starhotels data room: you are now Tier 3 — Approved, the full diligence checklist is open (received vs pending items), the shortlist deep pack is unlocked, and the new-diligence banner shows.

What it proves: the approval workflow closes the loop between buyer and deal team, and the new-diligence alert reaches registered buyers.

04 Verification dossiers — the honest score

Open the Starhotels dossier: 7 of 15 core fields verified (47%) — revenue and EBITDA cross-checked against public reports, the 33.3x EBITDA multiple flagged, not hidden. Then open the Germany dossier: 0 of 15 core fields verified (0%). That is not a bug — the Germany memorandum is price-only (no operating figures, no named seller entity, Waldorf key count disputed 152 vs 232). The dossier system surfaces the gap instead of inventing values.

What it proves: the PropertyShark-style dossier with a computed score (never hardcoded) — and that the score stays honest when the file is thin.

05 Prospectus builder — two samples, extract → generate

Open the Prospectus Builder. Click LOAD SAMPLE: STARHOTELS, then EXTRACT — the rule-based pass finds €340M / €108M / €3.6B, 31.8%, 2025, hotel. Review the structured fields, correct any, then GENERATE — the offering document appears with a verification checklist, downloadable as HTML or text. Then run it again with LOAD SAMPLE: GERMANY HOTELS — extraction finds €677.35M / €400M / €2.75M, 12.5%, 152 keys, 232 rooms.

What it proves: the Crexi-style ingest → extract → generate pipeline. Extraction is rule-based, not AI, and it is not verification — every generated figure must be checked against source documents.

06 Buyer CRM + gated alerts + engagement dashboard

Back in the back office: the CRM holds 6 fictional sample buyers across family office, sovereign wealth, private equity, venture capital, investment bank, and solo fund. Search, filter by type/status, add one (corporate email only — Gmail is refused), edit, delete, export/import JSON. In Gated Alerts, pick the Germany mandate and compose — the composer lists the matching hospitality buyers and generates copyable alert text (sending stays manual, by design). In the Engagement Dashboard, click SIMULATE DEMO ACTIVITY to see the per-mandate counts move, then COPY SELLER REPORT for the copyable report.

What it proves: the private qualified-buyer CRM with tags, gated alerts, and seller-side engagement reporting — all in the browser, no backend, no real buyer data in the repository.
